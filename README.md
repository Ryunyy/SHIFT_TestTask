# SHIFT Тестовое задание
Данный репозиторий хранит консольную утилиту, производящую обработку текстовых документов формата .txt в соответствии с поставленным заданием. 

## Инструкция пользователя
Данная утилита предназначена для анализа входных файлов на наличие строкового, целочисленного и дробного (с плавающей запятой) типов данных. Использование утилиты производится в командной строке и директории, содержащей исполняемый файл ```util.jar``` с обязательным вводом параметров, необходимых для работы утилиты. Утилита формирует три текстовых файла, хранящие в себе соответствующие типы данных - по одному на каждый из типов. Так же утилита поддерживает сбор краткой или полной статистики о типах и выводит ее в консоль.

1. Краткая статистика: количество элементов каждого из типов внутри входных файлов.

2. Полная статистика: минимальное, максимальное, среднее значения для целочисленного и дробного типов, а также сумма всех элементов для каждого из типов; самое короткое и самое длинное значение строкового типа.

Утилита позволяет задавать путь для результирующих файлов опцией '-o \<path\>', где \<path\> - путь к необходимой директории. Если параметр не указан, по умолчанию файлы бдут создаваться в той же директории, где находится исполняемый файл.

Помимо пути, утилита поддерживает добавление префикса для названия результирующих файлов опцией '-p \<prefix\>'. Например, если будет введено '-p sample-', то результирующие файлы будут иметь вид sample-integers.txt, sample-floats.txt, sample-strings.txt. По умолчанию файлы префикса не имеют. Префикс файла не должен содержать символов, мешающих определению файла операционной системой, поэтому вводится ограничение, указанное в описании параметра: запрещено наличие любого из символов \ / : * ? < > | или их комбинаций в префиксе.

Вводные файлы, если в команде утилиты указано только их имя, должны располагаться в директории исполняемого файла ```util.jar```, и иметь формат .txt, другие форматы обрабатываться не будут. Однако, если указывать полный путь до входного файла, а не только его имя в качестве параметра, утилита будет работать с предоставленными данными. Файлы должны существовать и быть доступны для чтения, иначе утилита завершится с соответствующим оповещением в консоли.

По умолчанию, утилитой собирается краткая статистика. Также, если не был введен параметр '-a', означающий "append" - добавление к существующим строкам в файлах, результирующие файлы будут перезаписаны. Файлы создаются по необходимости, поэтому, если в вводных данных не было какого-то типа данных, например, строкового, то и соответствующий результирующий файл создан не будет.

### Запуск утилиты
Для запуска утилиты на ОС пользователя должны быть установлены JRE или JDK с Java версии 18 и выше.

Команда запуска утилиты выглядит следующим образом:<br>
```
java -jar util.jar -s -a -p sample- in_1.txt in_2.txt
```
где ```java -jar util.jar``` - команда запуска описываемой утилиты, а ```-s -a -p sample- in_1.txt in_2.txt``` - пример ввода параметров.

Полный список параметров и их функций:<br>
```
Usage: [-s | -f] [-a] [-o <path>] [-p <prefix>] <file1.txt> <file2.txt> ...

Options supported:
        -s/-f | Show short (for '-s') or full (for '-f') statistic. Short by default.
        -a | Append results to output files. Overwrite by default.
        -o <path> | Select <path> as the output directory for files.
        -p <prefix> | Add <prefix> to the output files. E.g. -p out- -> out-strings.txt out-integers.txt etc. Prohibited symbols: \ / : * ? < > |
```
#### Порядок параметров
Указанные параметры обязаны итди в том порядке, в котором они указаны в инструкции и любое отклонение или лишние аргументы отслеживаются утилитой. Утилита будет запущена, когда все аргументы, вводимые в консоль, будут удовлетворять условиям использования. В противном случае утилита будет остановлена и в консоль будут выведены причины остановки с инструкцией использования.

#### Обязательные параметры
Обратите внимание, что все опции и их параметры, указанные в квадратных скобках [] - опциональны и не обязаны присутствовать в команде запуска утилиты. Однако параметры, указанные в треугольных скобках <> обязательно должны присутствовать. Таким образом, утилита требует обязательного наличия вводных файлов, а также путь для результирующих файлов и префикс названия результирующих файлов, если ипользуются опции '-o' и '-p' соответственно.

#### Конфликт параметров
В рамках утилиты существует два конфликтующих параметра: '-s' и '-f'. Они не могут идти в месте и утилита отслеживает их одновременное появление. Если ни один из параметров не представлен в команде запуска, по умолчанию будет использоваться параметр '-s'.

## Особенности реализации
Данная утилита разработана в соответствии с полученным техническим заданием. Для написания утилиты не использовались сторонние библиотеки или зависимости, подключаются только стандартные. Код был написан с использованием:

1. JRE/JDK с Java версии 18 и выше
2. Сборщик проекта Maven 4.0.0
3. IDE IntrlliJ Idea Community Edition 

Название исполняемого файла может отличаться от указанного, при воспроизведении кода на других ЭВМ, поскольку в моем случае имя настраивалось в свойствах проекта через IDE. На работу утилиты это не влияет, но если имя исполняемого файла другое, то в команде запуска необходимо использовать то, которое находится у вас.

Недостатки реализации:

Известно, что в случае, если число, находящееся в водных данных, превышает возможную вместительность типов Double или Long, с помощью которых реализовано хранение чисел с плавающей точкой и целочистенного типа соответственно, они будут помечены как строковый тип и помещены в соответствующий файл. Для этого можно дополнить решение, добавив в соответствующие классы обработку значений, превышающих объемом допустимые значения стандартных типов Java. Например, это можно сделать, обрабатывая все как строковые типы и храня их в типе String, но подразумевая, что это Integer или Double, ведь, технически, набор из 50 символов в диапазоне [0-9] со знаками + и - так же является целочисленным, но не уместится в стандартные типы. Однако в таком случае это требует написания полной логики под такие типы, начиная от операций сравнения, сложения, вычитания, поиска минимума и максимума, в связи с чем мною было прияно решение оставить этот недостаток и ограничиться лишь приведением строкового типа данных к Double и Long, обеспечив отлов исключений через try-catch.
